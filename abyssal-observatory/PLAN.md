# 심해 생물발광 관측소 구현 계획

## 목표와 범위
- 독립 실행 파일: `abyssal-observatory/abyssal-observatory.html`.
- 기존 Three.js 0.183.0 import map, 단일 HTML 구성, 절차적 지오메트리·텍스처 방식을 따른다. 추가 패키지나 외부 이미지/모델 없이 구현한다.
- 목표 경험: 어두운 관측실의 큰 창을 통해 발광 해파리와 해류에 움직이는 생태계를 감상하는 영화적 공간 데모.
- 실제 유체 해석, 완전한 생태 시뮬레이션, 게임 이동, 마우스 연동 카메라는 범위 밖이다.

## 구현 전 확인
- 저장소 지침과 README, 성소 및 포털 실험실의 렌더러·후처리·FPS·종료 처리·절차적 재질 코드를 직접 읽는다.
- 재사용할 패턴만 필요한 만큼 가져온다. 기존 데모 수정이나 공용 모듈 리팩터링은 하지 않는다.
- WSL에서 가능한 JS 구문 검사, 정적 서버, 브라우저 자동화 도구를 확인한다.

## 장면과 미술
1. 전경: 두꺼운 원형 또는 둥근 사각 관측창 프레임, 바닥 패널, 소수의 따뜻한 계기등. 프레임이 해양 주제를 명확하게 전달하도록 한다.
2. 중경: 크기와 유영 위상이 다른 해파리 5~8마리. 청록·푸른 발광을 기본으로 하고 소수의 보라색 포인트를 사용한다.
3. 후경: 비대칭 해저 바위, 소수 해초, 해저 케이블 또는 관측 장치. 안개와 명도 차로 깊이를 만든다.
4. 부유 입자와 작은 물고기 군집을 추가하되 창과 주인공 실루엣을 가리지 않게 한다.
5. 창의 유리는 약한 오염·가장자리 반사만 표현한다. 굴절이나 투명 정렬 문제로 장면을 가리지 않게 하며, 사실적 광학 시뮬레이션이라고 표기하지 않는다.

## 움직임과 렌더링
- 해파리: 종 모양 몸체의 수축·팽창, 약간 늦게 따라오는 촉수, 완만한 상하 이동과 방향 변화. 공유 재질과 적절한 분할 수를 사용한다.
- 해류: 하나의 시간·강도 값에 해초, 입자, 유영 편향을 연결한다. 프레임 수가 아닌 delta time으로 진행한다.
- 물고기: 소규모 군집 또는 경로 기반 군집 연출을 우선한다. GPGPU 도입은 필수가 아니다. 실제 boids를 구현하지 않으면 군집 연출로 설명한다.
- 조명: 외부의 차가운 빛, 실내의 따뜻한 계기등, 제한된 블룸. 탐조등의 실제 조명과 연출용 빛줄기 가시성을 함께 전환한다.
- 카메라: 실내에서 창에 접근하고 천천히 옆으로 이동하는 매끄러운 반복 경로. 벽·프레임 관통 방지. 마우스 이동에는 반응하지 않는다.

## UI·접근성·수명 관리
- 한국어 제목·간단한 설명, 탐조등 토글, 해류 강도, 일시정지/재생, 자동 카메라 토글, 갤러리 복귀 링크, FPS 표시.
- 일시정지는 시뮬레이션과 자동 카메라를 함께 정지하되 UI는 계속 작동한다.
- reduced-motion 환경은 자동 카메라를 기본 중지하고 불필요한 움직임을 줄인다. 키보드 포커스와 컨트롤 label을 제공한다.
- 좁은 화면에서도 캔버스와 컨트롤이 잘리지 않게 한다. DPR 상한과 인스턴싱/공유 geometry로 비용을 제한한다.
- resize, 백그라운드 복귀 시 큰 시간 점프, pagehide/pageshow와 이벤트·GPU 리소스 정리, WebGL 초기화 실패 메시지를 처리한다.

## 단계별 검증과 완료 조건
1. 기본 장면과 카메라: 첫 화면에서 관측소와 해파리가 식별되고 창 가림·클리핑이 없는지 확인한다.
2. 애니메이션·효과: 움직임의 연속성, pause/resume, 해류와 탐조등 상태를 확인한다.
3. 데스크톱/모바일 크기, reduced-motion, 리사이즈, 뒤로 가기/재진입을 점검한다.
4. JS 구문, 로컬 HTTP 응답과 링크, 가능한 경우 실제 브라우저의 콘솔 오류·스크린샷·컨트롤 동작을 검증한다. FPS는 실제 관측한 환경과 수치만 보고한다.
5. 실제 변경과 최초 요구를 다시 검토하고 중대한 문제를 수정한다. 브라우저 검증이 불가능하면 Partially Verified로 명확하게 보고한다.

## 공통 파일 소유권과 병렬 작업
- 이 작업은 `abyssal-observatory/` 및 루트 `index.html`, `README.md`의 유일한 수정 담당이다.
- 별도 기계식 천문대 작업은 `clockwork-orrery/`만 수정한다. 그 폴더의 파일은 수정하지 않는다.
- 두 데모 구현 상태를 확인한 뒤 갤러리 카드·개수·README 목록과 조작 설명을 한 번에 갱신한다. 계획만 존재하는 데모를 완성됐다고 문서화하지 않는다.
- 천문대 작업의 결과는 해당 작업의 상태/결과를 읽어 확인한다. 필요하면 작업 메시지로 등록에 필요한 내용을 요청한다.
- 최종 보고에 구현 내용, 주요 파일, 실행한 검증, 미검증 사유, 남은 위험, Verified/Partially Verified/Blocked/Failed 상태를 포함한다.
