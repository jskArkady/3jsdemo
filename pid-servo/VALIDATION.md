# PID 서보 실험대 — 구현 및 검증

## 산출물
- 진입점: `pid-servo/pid-servo.html`
- 갤러리 설명: **레일 위 카트의 목표 추종으로 P·PI·PID, 힘 포화와 anti-windup, 유한시간 외란을 비교하는 제어 실험대.**
- 기존 Three.js 0.183.0 import map·동적 import 실패 안내·절차적 장면·AbortController 수명 관리 패턴 사용. 새 런타임 의존성 없음.
- HTML 하나로 실행하며 검증 스크립트 2개는 실행에 필요하지 않음. 자신의 폴더만 변경.

## 실제 조작
게인 Kp/Ki/Kd, 질량, 점성마찰, 목표/진폭, 힘 제한; 7개 프리셋(P, PI, PID, 임계 PD, 큰 오버슈트, 포화 AW ON/OFF); step/sine; anti-windup 토글; +2 N × 0.5 s 외란; 일시정지/재생, 초기화, 5 ms 한 주기, 0.25/1/2배속; 정면/사선/자동 카메라.

게인·목표·AW 변경은 위치·속도·필터 속도와 시간을 유지하며 적분과 지표·그래프 구간을 초기화한다. 질량·점성·힘 제한·신호·프리셋은 실험 전체를 초기화한다. 초기화는 재생/정지 상태와 카메라를 유지한다. 외란은 다음 제어 주기부터 시작하며 재클릭하면 100주기 펄스를 다시 시작한다. 프리셋은 모두 x=v=I=0, 목표 1 m, 외란 없음으로 비교한다.

## 모델과 단위
- `m x'' = u − b x' + d`, m=1 kg, b=0.8 N·s/m 기본. 중력·정지마찰·레일 충돌 제외.
- e=r−x, `u_raw = Kp e + Ki I − Kd vf`, 기본 Kp=12 N/m, Ki=3 N/(m·s), Kd=4 N·s/m, 제한 ±10 N.
- 고정 0.005 s: 측정 속도 저역필터(τ=0.02 s, 정확한 지수 갱신) → 적분 후보 → 조건부 anti-windup → 포화 → 일정한 입력의 정확한 질량–점성마찰 해. 임계 PD 프리셋은 τ=0.
- anti-windup은 후보 힘이 제한 안이거나 적분 방향이 포화에서 회복하는 방향일 때 적분한다. 측정 미분으로 목표 변경에 따른 미분 kick을 피한다. 목표 step에 비례 제어 kick은 정상적으로 발생한다.
- sine 0.2 Hz, 목표 슬라이더는 부호 있는 진폭. 외란은 힘 펄스이지 순간 속도 변경이 아니다.
- 레일 1 단위=1 m, 눈금 0.25 m. 화살표 0.055 m/N. |x|>2.5 m 또는 비유한 상태를 감지하면 정지·초기화 안내. 위치 clamp 없음.
- 프레임 delta 최대 0.05 s, 프레임당 최대 20주기, 배속은 주기 수에 적용. 느린 GPU에서는 실제 시간보다 느려질 수 있다. 최근 801개(20 s)의 그래프 자료만 유지. DPR≤1.5.
- Step 지표는 구간 시작→목표 변위 기준 방향성 오버슈트. 최대오차는 구간 전체, 정착은 ±2% 변위(최소 0.005 m) 안에서 관측상 1초 연속 체류한 구간의 시작 시각이다. 이탈하면 판정 취소; 외란 예약도 체류 시간을 취소한다. 미래 정착을 보장하지 않는다. Sine은 RMS 오차로 표시한다.
- 참고: [University of Michigan CTMS PID](https://ctms.engin.umich.edu/CTMS/?example=Introduction&section=ControlPID), [System Modeling](https://ctms.engin.umich.edu/CTMS/?example=Introduction&section=SystemModeling). 직접 열기는 403이었으며 검색에 노출된 원문 수식과 로컬 해석·수치 결과를 대조했다. CTMS의 질량–스프링–댐퍼 모델에서 스프링 계수를 0으로 둔 경우다.

## 브라우저 검증
검증 명령: `flock /tmp/threejs-stem-browser.lock node pid-servo/validate-browser.cjs`.
기존 Playwright 1.57.0 및 WSL Chromium/SwiftShader, 로컬 HTTP 임의 포트를 사용한다. 초기 sandbox의 HTTP listen EPERM 이후 승인된 실행 범위로 동일 검증을 실행한다. 다른 작업의 서버·잠금은 변경하지 않는다.

통과 항목:
- 실제 RAF로 1초 이상 계산·렌더 진행(검증 관측 64프레임). 시간을 인위적으로 빠르게 넘긴 FPS 주장이 아님.
- pause는 물리 시간과 자동 카메라 시간을 함께 정지. 한 주기는 정확히 0.005 s. 정지 중 외란 예약 후 100주기에서 종료, 다음 주기에 d=0.
- 재생/정지/초기화/모든 프리셋/게인/질량/마찰/목표/힘 제한/AW/신호/배속/카메라 버튼 조작. 목표·게인 변경 시 plant 상태 유지 확인.
- 마우스 이동이 카메라를 바꾸지 않음. 정면/사선 변경 확인.
- 1440×1000, 390×844, 844×390 화면 캡처 검토. 모바일 가로 넘침 발견→grid 최소 너비 수정→재검증 통과. 작은 화면은 수직 스크롤로 모든 컨트롤에 접근하며 한 화면에 전부 고정하지 않음.
- reduced-motion 초기 정지·자동 카메라 OFF, 키보드 Tab 갤러리 링크 접근.
- synthetic visibilitychange 및 persisted pagehide/pageshow로 RAF 중지·재개와 시간 기준 초기화 확인. non-persisted pagehide는 dispose, 반복 dispose 안전, 종료 뒤 렌더 프레임 불변.
- CDN 차단 시 실패 안내. webglcontextlost 이벤트에 오류 안내와 dispose 확인.
- 정상 실행 pageerror/console error 0건.
- 스크립트 구문 검사: HTML의 두 계산/실행 script를 `/tmp/pid-servo-script-{0,1}.mjs`로 추출해 `node --check`; 두 검증 CJS도 `node --check` 통과.

스크린샷은 `/tmp/pid-desktop.png`, `/tmp/pid-390.png`, `/tmp/pid-844.png`이며 테스트 재실행 시 갱신한다. 런타임 파일은 아니다.
